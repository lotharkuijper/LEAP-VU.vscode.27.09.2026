# Canvas (LTI 1.3, 2026-10-23)

Any change here is a security decision (login, roles, account linking): use the `secure-change` skill and suggest a review by the `security-reviewer` agent.

- A course with access route `canvas`/`canvas_open` gets a **Canvas link** in Cursussen beheren (`CanvasLinkDialog`, for the admin and the course's teachers): `<app>/lti/launch?course=<id>`. The teacher adds it in Canvas as an External tool module item (new tab). Code: `server/lti/lti.js` (routes wired in `server/lti/routes.js`), migration `20261023100000_canvas_lti` (+ rollback), instructions for the VU Canvas admins: `docs/canvas/canvas-koppeling.md`.
- Launch: `/lti/login` (OIDC start; state + nonce in process memory, single use; state cookie `SameSite=None; Secure; Partitioned`, Secure also on localhost so Canvas can post back from another site, Partitioned so it also works in a Canvas iframe) → Canvas → `POST /lti/launch` with a signed id_token, verified with `jose` against the platform JWKS (iss, aud, max age, nonce, deployment, message type). Then `processLaunch`: account by `lti_identities` (issuer + Canvas sub), else by exact e-mail (`likeExact`: `_` and `%` are no wildcards) and only to an account whose confirmed login address is that e-mail, else a new confirmed account; Canvas course roles Instructor/TA → `teacher`, Learner → `student` (only roles in THIS course count, never institution roles), a teacher is never downgraded, and a Canvas teacher also gets the teacher profile; `lti_course_links` records the Canvas course; `last_active_course_id` is set. Login without password: `generateLink('magiclink')` → `/lti/start#token_hash=…` (`LtiStartPage`, `verifyOtp`, fragment removed at once). Errors go to `/lti/start#error=<code>` with a translated message.
- Afterwards students who came via Canvas log in directly with a one-time code by e-mail (`POST /api/auth/email-code`, `EmailCodeLogin` on the login page): only for accounts with an `lti_identities` row, `shouldCreateUser: false`, the same answer whether or not the address exists, max 3 per e-mail per 15 min. The auth e-mail hook (`server/account/authEmailHook.js`) has a `magiclink` text with the code itself (`email.auth.magiclink.*`).
- Settings: the Canvas environments (`{ issuer, clientId, deploymentIds, authUrl, jwksUrl }`) are NOT secret. Since 2026-10-29 the admin sets them in Beheer → Instellingen → Canvas-koppeling (`CanvasPlatformsPanel`, `GET/PUT /api/admin/lti-platforms`, chatbot_prompts row `__lti_platforms__`, logged in `leap_setting_changes`; `createPlatformRegistry` merges them with `LTI_PLATFORMS` from the environment, env wins, effective without restart). For Instructure's Canvas cloud the issuer is `https://canvas.instructure.com` (also for vud.instructure.com) and `canvasEndpoints` fills in the sso.canvaslms.com URLs. A refused launch from an unknown environment or deployment is remembered in process memory (`createUnknownLog`, last 5) and shown in that panel with "Neem over". `LTI_TOOL_PRIVATE_JWK` (`node scripts/lti-keygen.mjs`) stays in Key Vault only; it is not needed for launches (only for NRPS later). Optional `LTI_APP_URL`. With no environment at all the routes refuse politely and the dialog shows "not configured".
- The Canvas link must carry `?course=<id>`: Canvas pre-fills the module item URL with the bare `/lti/launch` from the Developer Key, so the dialog tells the teacher to replace it (`canvasLink.step2`, `urlNote`). A bare launch only works for a Canvas course already linked via `lti_course_links`. Dev: Vite proxies `/lti/(login|launch|jwks|config.json)` to the API. Tests: `server/__tests__/lti.test.js` (real signatures, forged/expired/replayed messages).

## Canvas group assignments for projects (2026-10-27)
- The project link is `/lti/launch?course=<c>&project=<p>`, added in Canvas as a GROUP ASSIGNMENT (`assignment_selection` placement). Custom fields `canvas_group_id=$com.instructure.Group.id`, `canvas_group_name=$com.instructure.Group.name` arrive only from a group assignment (otherwise the literal variable name, ignored). `processLaunch` puts a student in the LEAP group with `external_ref = canvas:<issuer>:<groupId>` (created with the Canvas name if needed) and redirects into the room (`next` on `/lti/start`). A student already in an active group stays there (teacher moves win). NRPS read-only scope is requested for a later pre-sync of group membership; not used yet. `server/__tests__/projectGroups.test.js`, `server/__tests__/lti.test.js`. Group modes: see `projects-personas.md`.
